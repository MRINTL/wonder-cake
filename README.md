# WonderCake — демо-версія сайту кондитерської

Монорепо: вітрина на **Astro 7 + Tailwind 4** і адмінка на **Payload CMS 3 (Next.js 16) + SQLite**.
Весь контент — український, редагується в CMS.

```
WonderCake/
├── apps/
│   ├── cms/          Payload CMS: колекції, глобальні налаштування, seed
│   └── web/          Astro-вітрина (статична збірка для GitHub Pages)
└── package.json      npm workspaces + скрипти
```

## Швидкий старт

```bash
npm install          # один раз
npm run seed         # створює SQLite-базу і демо-контент
npm run dev          # cms → :3000, web → :4321
```

| Що | Адреса |
| --- | --- |
| Вітрина | http://localhost:4321/wonder-cake/ |
| Адмінка CMS | http://localhost:3000/admin |
| REST API | http://localhost:3000/api/products |

**Демо-доступи**

- CMS (адміністратор): `admin@wondercake.ua` / `wondercake`

`npm run seed` очищає товари, категорії, свята й сторінки та наповнює їх заново —
акаунти при цьому зберігаються.

## Що редагується в CMS

- **Товари** — назва, слаг, ціна / стара ціна, одиниця (кг / шт / набір), мінімальна вага,
  фасування, опис, склад, алергени, калорійність, бейджі (хіт / новинка / акція),
  свята, теги для пошуку, фото, галерея, наявність, лічильник замовлень.
- **Категорії** — назва, розділ меню (торти / десерти), ілюстрація-заглушка, порядок.
- **Свята** — назва, емодзі, дата, опис.
- **Сторінки** — «Про нас», політика, умови (вступ + секції з абзацами).
- **Головна сторінка** (глобал) — hero, лічильники, тексти блоків, CTA, FAQ.
- **Налаштування сайту** (глобал) — назва, слоган, контакти, соцмережі, умови доставки, футер.

## Технічні рішення

**Стилі.** Кольори задані токенами Tailwind 4 у `apps/web/src/styles/global.css`:
`--color-primary #e20b6c`, `--color-accent #69cdde`, `--color-navy #071a3b`, світлий фон `--color-cream`.
Верстка mobile-first, класи-утиліти `btn`, `card`, `section`, `container-page`.

**Зображення.** Замість фото товарів рендеряться SVG-заглушки
(`apps/web/src/components/ProductImage.astro`) — форма береться з категорії, палітра з id товару.
Щойно у CMS з'явиться завантажене фото, компонент автоматично покаже його замість заглушки.

**Кошик і обране** живуть у `localStorage` (`apps/web/src/scripts/store.ts`) —
без бекенду, стан переживає перезавантаження й спільний для всіх сторінок.
Оформлення замовлення й оплата у демо не підключені.

**Статична збірка.** Вітрина збирається в чистий HTML (`output: 'static'`, `base: '/wonder-cake'`).
Дані з CMS забираються лише під час збірки; фільтри, сортування й пошук працюють у браузері,
а стан фільтрів живе у `?kategoriya=…&sort=…`. Внутрішні посилання будуються через `url()`
з `apps/web/src/lib/url.ts` — він додає base і слеш у кінці.

**Стійкість до недоступної CMS.** Якщо Payload не запущено, запити повертають порожні
відповіді — збірка пройде, але сторінки будуть без товарів.

## Публікація на GitHub Pages

```bash
npm run dev:cms        # термінал 1 — CMS має працювати під час збірки
npm run deploy:pages   # термінал 2 — збирає вітрину і пушить dist у гілку gh-pages
```

У репозиторії: Settings → Pages → Source: *Deploy from a branch* → `gh-pages` / `root`.
Сайт: `https://<логін>.github.io/wonder-cake/`. Файл `public/.nojekyll` обовʼязковий —
без нього GitHub не віддасть папку `_astro` зі стилями.

## Корисні команди

```bash
npm run dev            # обидва застосунки
npm run dev:cms        # тільки CMS
npm run dev:web        # тільки вітрина
npm run seed           # перезалити демо-контент
npm run build          # прод-збірка cms + web
npm run generate:types -w @wondercake/cms   # типи Payload
```

## Що навмисно не робили в демо

- оформлення замовлення, оплата, історія замовлень;
- мультимовність (сайт лише українською);
- завантаження реальних фото — використані SVG-заглушки;
- юридичні тексти написані як плейсхолдери.
